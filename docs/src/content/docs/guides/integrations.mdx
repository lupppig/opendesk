Integrations connect the tools your team already works in. Once one is connected, Ollie can look things up there and, after someone approves, create and update things for you: "open a Linear issue for this ticket", "is this error in Sentry?", "check this customer's invoices in Stripe".

Every integration is the product's own **MCP server** (Model Context Protocol). Products not in the list connect by URL, including internal tools that run an MCP server. Admins manage them in **Settings, Integrations**.

<Legend>

1. **Add by URL**: connect any MCP server that is not in the list.
2. **Connected**: what Ollie uses for everyone in the workspace, with how many tools it has and how many ask before acting.
3. **Categories**: issues, docs, chat, CRM, payments, files and automation.
4. **Catalog**: each card says how it signs in (account sign-in or access token) and has **Connect**.

## Connect a product

<Steps>
<Step title="Click Connect on its card">

The connection is shared by the workspace, so an admin signs in once and everyone's Ollie can use it.

- **Account sign-in** (Linear, Jira and Confluence, Sentry, Notion, Slack, Stripe, GitHub and most others) opens the product's own sign-in page and brings you back to opendesk. For GitHub, install the opendesk app on the repositories Ollie may use.
- **Access token** asks for a token you create in that product. GitHub asks for one on a self-host without a GitHub App: give it only the access Ollie needs, for example a fine-grained token for the repositories it may use.

<Screenshot src="/guides/integrations/token" alt="The Connect GitHub dialog: the Access token field with its Create one link ringed as 1, and the note that Ollie only looks things up on its own ringed as 2" />

</Step>
<Step title="Choose its tools">

Open a connected integration to see its tools. Each one is marked **Looks up** (runs on its own) or **Asks first** (waits for approval). The product itself says which of its tools only look things up. If you'd rather approve one of those too, switch on its **Ask first**. A tool that changes something can instead be set to **Runs without asking**, so Ollie uses it as soon as it decides to; **Ask first** wins if both are on. Switch off any tool you don't want Ollie to use, or switch the whole integration off.

<Screenshot src="/guides/integrations/tools" alt="The Linear integration opened: a Looks up tool ringed as 1, an Asks first tool ringed as 2, a tool's switch ringed as 3, and the integration's own switch and actions menu ringed as 4" />

</Step>
<Step title="Keep it up to date">

The **⋯** menu has **Check for new tools**, to fetch the list again after the product adds tools, **Sign in again** (for account sign-in), and **Disconnect**. Disconnecting deletes the sign-in; links already on tickets stay.

<Screenshot src="/guides/integrations/menu" alt="The actions menu of an integration ringed as 1: Check for new tools, Sign in again and Disconnect" />

</Step>
</Steps>

### Connect any MCP server

Click **Add by URL**, paste the server's URL (it usually ends in `/mcp` or `/sse`), optionally name it, and choose how it signs in: **Sign in** with an account, an **Access token**, or **No sign-in**. Servers that speak Streamable HTTP or the older HTTP and SSE transport both work.

## Use it on a ticket

<Steps>
<Step title="Pick a shortcut, or ask">

On a ticket, Ollie's section shows shortcuts for your connected tools under **In your tools**, such as "Create a Linear issue" or "Find related Linear issues". You can also just ask Ollie in your own words.

</Step>
<Step title="Approve the change">

Anything that creates or changes something shows an approval card first, marked **Runs in Linear** (or the product it runs in), with the title, fields and text. When there is more than the card can show, it says so ("3 more fields", or that some values are cut short), and **Show all arguments** opens everything the change will send, exactly as it is sent. Nothing happens until the person who asked approves it, except with a tool set to **Runs without asking**: then the step in Ollie's panel is marked **Ran without asking** and shows what it sent.

<Screenshot src="/guides/integrations/approval" alt="Ollie's approval card for a Linear issue: Runs in Linear ringed as 1, the title, team and priority ringed as 2, and Deny and Approve ringed as 3" />

</Step>
<Step title="Find it on the ticket">

When Ollie creates something from a ticket, it links it back. The ticket's **Linked** section lists what the ticket points to in other tools, and the timeline records "Ollie linked ...". Removing a link leaves the item in the other product as it is.

<Screenshot src="/guides/integrations/linked" alt="A ticket's details: the In your tools shortcuts ringed as 1, and the Linked section with a Linear issue created by Ollie ringed as 2" />

</Step>
</Steps>

<Callout>

Integrations are for your team's Ollie. To let the [AI agent](/guides/ai/#the-ai-agent-for-chat-and-email) use your own tools when it answers customers, connect them in **Settings, AI agent, Tools** instead.

</Callout>

## Ticket panels

A ticket panel shows, beside the ticket and under the contact, what another product knows about the ticket's contact: their orders in your Shopify store, or anything a system of your own can answer, such as an ERP's orders and supplier dates, a billing system's subscription or a CRM's account. Panels only read. They load when someone opens the ticket, each on its own, and a product that is slow or down shows a short note instead of holding the ticket up. Admins add them in **Settings, Integrations, Ticket panels**, or from the **Shopify** and **Your own data** cards of the integrations catalog. Tickets show a panel's name above what it answers: to change it, open the panel's menu and click **Rename**.

<Steps>
<Step title="Shopify: create an app for your shop">

In Shopify's [Dev Dashboard](https://dev.shopify.com/dashboard), create an app. On its version, give the Admin API the **read_customers** and **read_orders** scopes, release the version and install the app on your shop. Shopify shows orders from the last 60 days unless the app also has **read_all_orders**. The app's **Settings** show its **Client ID** and **Client secret**.

The app must belong to the shop's own Shopify organization: create it while signed in to the organization the shop is in.

</Step>
<Step title="Add the panel">

Click **Add a panel**, keep **Shopify**, enter the shop's `myshopify.com` domain and paste the client ID and secret. opendesk checks them with the shop before saving them, then asks Shopify for a new access every 24 hours on its own. An app made in Shopify admin before 2026 still has an Admin API access token: choose **An access token** and paste it instead. Each ticket whose contact has an email then shows the customer (with their order count, what they spent and their tags) and their last five orders: number, date, total, payment and fulfilment status, each line with its unit price, the city and country it ships to and the shipping method, discount codes, what was refunded, and the parcel's tracking link. A cancelled order is marked with its date. Every order opens in Shopify admin. The city and country need the app's access to customer addresses (protected customer data in the Dev Dashboard); without it the orders show without them.

</Step>
<Step title="Shopify: choose what tickets show">

Open the panel's menu and click **Choose what shows**. Tick the customer's fields (tags, their email in the store, number of orders, total spent) and each order's (payment and fulfilment status, products and their unit prices, city, country and shipping method, discount codes, refunded amount, tracking), and how many orders show, from one to five. A preview beside the list shows a ticket as it will look. What you leave out is not read from Shopify at all, and the customer's name and each order's number, date and total always show. If your store tags customers for marketing (newsletter, signup source), untick **Tags**. **Use the defaults** puts back what a new panel shows.

</Step>
<Step title="A system of your own: add a panel from a URL">

Choose **From a URL** and enter an https address of yours. opendesk shows its signing secret once: keep it. When a ticket is open, opendesk posts the ticket, its contact and the order or invoice numbers it finds in the ticket to that URL, and shows what it answers: cards, labelled values, lists and short notes, in the same look as the Shopify panel.

</Step>
<Step title="Choose which numbers it looks for">

Open the panel's menu and click **Order references**. opendesk looks for them in the ticket's subject and its newest messages (never a deleted one), and sends only what it finds, never the messages. The default finds a `#` and digits (`#1042`) or a few capitals and digits (`S00042`, `SO-2026-0042`, `INV/2026/00012`, `PO4471`), so years, prices, postcodes and phone numbers are left alone. Write your own regular expression if your numbers look different (with a group, only the group is sent; large repeat counts such as `{100}` are refused), try it on a sample text, or leave it empty to send none.

</Step>
</Steps>

### What your URL receives

A `POST`, signed like webhook deliveries (`OD-Signature: t=<unix>,v1=<hex>`, the HMAC-SHA256 of `"<t>.<body>"` with the secret):

```json
{ "panel_id": "…", "workspace_id": "…", "refresh": false, "locale": "fr",
  "ticket": { "id": "…", "number": 1042, "subject": "Where is my order S00042?",
              "references": ["S00042"] },
  "contact": { "id": "…", "email": "ada@example.com", "name": "Ada Buyer",
               "emails": ["ada@example.com"], "phone": "+32 470 12 34 56" } }
```

`references` holds at most ten numbers, `phone` is there when the contact has one, and `refresh` is true when an agent clicked the refresh button. `locale` is the language the agent's app is in (`en`, `fr`, `de`, a lowercase language code), so you can write your titles, labels and notes in it; it is missing when the app did not say, so keep a default. A new or deleted message shows in them on the next open; a changed phone or an edited note within a minute, or at once on refresh. A workspace's panels read tickets at most 60 times a minute together; past that a panel says so until the minute ends, and a ticket it already read still shows. opendesk only ever adds fields, so ignore the ones you don't use.

### What it answers

At most 64 KB of JSON with `"version": 2` and a list of `blocks`. Four kinds:

- **card**: one record, such as an order, an invoice, a subscription or a deal. A `title` (with an optional `url`), a `subtitle`, `badges`, `links`, labelled `fields`, `lines` (with a `quantity`) and a `footer` for totals. Agents fold and open any card from the arrow in its header, or with a click on the header; `"collapsed": true` makes it start folded to its title, links, subtitle and badges. What an agent chooses stays while they work the ticket, through refreshes and newer answers. An optional `id` keeps a card known across answers when its title can change; without one, its title does.
- **fields**: labelled values, `{ "label", "value", "url"? }`.
- **list**: rows, `{ "title", "subtitle"?, "value"?, "badge"?, "url"?, "links"? }`.
- **note**: one short sentence, `{ "text", "tone"? }`.

A value is plain text or a number, or one of three typed values that opendesk writes in each agent's own language and timezone:

- `{ "type": "date", "value": "2026-11-12", "relative": true }`: a day, or a time such as `2026-11-12T09:30:00Z`. `relative` adds "in 3 days" or "5 days ago".
- `{ "type": "money", "amount": "1890.00", "currency": "EUR" }`
- `{ "type": "badge", "text": "Overdue", "tone": "danger" }`

`links` open the same record in each tool that holds it, as small buttons after the title: up to 5 of `{ "label", "url", "icon"? }`. The label names the button and shows as its tooltip. The icon is one opendesk draws itself: `external-link`, `store`, `shopping-cart`, `receipt`, `file-text`, `truck`, `package`, `user`, `building`, `phone`, `mail`, `credit-card`, `map-pin`, or the logo of a product opendesk ships, such as `shopify`, `odoo`, `stripe` or `paypal`. Without one the button shows the label's first letter; opendesk never loads a picture from your link's site.

Tones are `neutral`, `info`, `success`, `warning` and `danger`. Everything shows as plain text and https links, never HTML. Anything opendesk does not recognize, such as a block type from a later version, is skipped and the rest still shows. Up to 10 blocks show, with 30 fields, 20 lines and 20 rows each. An answer is kept for a minute unless it says otherwise with `"cache_seconds"` (0 to 600), for each language apart. Answer `204` or `404` when you know nothing about the contact.

#### A minimal server

Python with the standard library only: it checks the signature (and that it is less than five minutes old) before answering. Replace `find_order` with a lookup in your own system.

```python
import hashlib, hmac, json, os, time
from http.server import BaseHTTPRequestHandler, HTTPServer

SECRET = os.environ["OPENDESK_PANEL_SECRET"].encode()  # the pnsec_… secret

def signed(body: bytes, header: str) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(",") if "=" in p)
    t, v1 = parts.get("t", ""), parts.get("v1", "")
    if not t.isdigit() or abs(time.time() - int(t)) > 300:
        return False
    mac = hmac.new(SECRET, t.encode() + b"." + body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(mac, v1)

def find_order(refs, email):
    return {"number": refs[0], "url": f"https://erp.example.com/so/{refs[0]}", "due": "2026-11-12"} if refs else None

class Panel(BaseHTTPRequestHandler):
    def do_POST(self):
        body = self.rfile.read(int(self.headers.get("Content-Length", 0)))
        if not signed(body, self.headers.get("OD-Signature", "")):
            return self.send_error(401)
        req = json.loads(body)
        order = find_order(req["ticket"]["references"], req["contact"]["email"])
        if not order:
            self.send_response(204)
            return self.end_headers()
        delivery = {"fr": "Livraison", "de": "Lieferung"}.get(req.get("locale"), "Delivery")  # in the agent's language
        answer = {"version": 2, "blocks": [{"type": "card", "title": f"Order {order['number']}", "url": order["url"],
            "fields": [{"label": delivery, "value": {"type": "date", "value": order["due"], "relative": True}}]}]}
        out = json.dumps(answer).encode()
        self.send_response(200)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(out)))
        self.end_headers()
        self.wfile.write(out)

HTTPServer(("", 8080), Panel).serve_forever()  # behind your https proxy
```

An answer from before blocks, `{ "sections": [ { "title", "items": [ { "label", "value", "url"? } ] } ] }`, still shows as it always has. ## Security

- Sign-ins and tokens are stored encrypted and are never shown again, in the app, the API, events or logs.
- opendesk only talks to public https servers, and checks every address a server names (its sign-in pages included) the same way.
- Account sign-in uses OAuth with PKCE. The sign-in is bound to the browser that started it.
- Connecting, changing and disconnecting an integration or a ticket panel is recorded in the audit log.
- A ticket panel never looks up the contact of a ticket the reader cannot see.
- What a connected product returns is treated as data: it cannot approve changes or change Ollie's instructions.

## Self-hosting

Integrations work the same on a self-host. Most products register opendesk on their own the first time an admin signs in. For a product that only accepts apps registered in advance, register an OAuth app there with the redirect URL `https://<your API URL>/v1/integrations/oauth/callback`, then set:

```bash
MCP_<KEY>_CLIENT_ID=...
MCP_<KEY>_CLIENT_SECRET=...   # if the product issued one
```

`<KEY>` is the integration's key in capitals, for example `MCP_SLACK_CLIENT_ID` (Slack and Box only accept apps registered in advance; GitHub signs in with a GitHub App when one is set and asks for a token otherwise; the compose file passes their variables). For another product, add its two variables to the `opendesk` service's `environment` in `docker-compose.yml`. The API for integrations, ticket links and ticket panels is in [the contract](https://github.com/useopendesk/opendesk/blob/main/contracts/integrations.md).
